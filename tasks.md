# Этапы выполнения задания

## Базовый уровень

### Этап 1. Подготовка Python-проекта

- Выбрать небольшой существующий Python-проект или создать собственный.
- Разместить исходный код в своём GitHub-репозитории.
- Настроить локальное окружение и установить необходимые зависимости.
- Убедиться, что проект запускается и подходит для проведения автоматизированных проверок.

### Этап 2. Настройка GitHub Actions

- Создать CI-конвейер с использованием GitHub Actions.
- Настроить автоматический запуск при `push` и `pull_request`.
- Добавить установку Python и необходимых зависимостей.

### Этап 3. Интеграция инструментов анализа

- Подключить инструмент статического анализа качества кода (например, Pylint).
- Подключить инструмент поиска потенциальных проблем безопасности (например, Bandit).
- Подключить инструмент проверки зависимостей (например, pip-audit).
- Обеспечить выполнение всех выбранных проверок в CI-конвейере.

Допускается использование альтернативных инструментов с аналогичным назначением.

### Этап 4. Анализ результатов

- Запустить CI-конвейер и изучить результаты проверок.
- Определить выявленные проблемы и оценить их значимость.
- Предложить рекомендации по устранению обнаруженных проблем.
- Продемонстрировать повторный запуск проверок после изменения кода или настроек.

### Этап 5. Подготовка отчёта

Составить краткий отчёт `REPORT.md`, включающий:

1. Описание выбранного Python-проекта.
2. Перечень использованных инструментов.
3. Выявленные проблемы и результаты проверок.
4. Рекомендации по устранению проблем.
5. Выводы о работе CI-конвейера.

## Дополнительные задания

### Повышенный уровень (оценка 9)

Настроить автоматическое формирование и сохранение отчетов проверок в виде артефактов GitHub Actions.

Результат: отчеты доступны для просмотра и скачивания после завершения конвейера.

### Экспертный уровень (оценка 10)

Реализовать механизм автоматической блокировки CI-конвейера при обнаружении проблем безопасности, соответствующих заранее определенным критериям.

Студент самостоятельно выбирает инструмент анализа, уровень критичности и способ реализации блокировки.

Необходимо:

1. Определить условия, при которых конвейер должен завершаться с ошибкой.
2. Настроить автоматическую проверку этих условий.
3. Продемонстрировать, что при обнаружении соответствующей проблемы workflow получает статус failure.
4. Устранить проблему и продемонстрировать успешное выполнение workflow со статусом success.
5. Описать выбранные критерии и механизм блокировки в отчете.

Важно: блокировка должна зависеть от фактических результатов анализа безопасности, а не от искусственно заданного завершения workflow с ошибкой.
