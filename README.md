# Внедрение практик безопасности в CI/CD-конвейеры (DevSecOps)

## Описание задания

Цель задания — познакомиться с практиками DevSecOps и научиться интегрировать автоматизированные проверки безопасности в процесс разработки программного обеспечения.

Для выполнения задания необходимо выбрать небольшой существующий Python-проект или создать собственный. Проект должен позволять настроить автоматизированные проверки качества и безопасности кода и продемонстрировать обнаружение и устранение выявленных проблем.

Необходимо настроить CI-конвейер на базе GitHub Actions, подключить инструменты статического анализа кода и проверки зависимостей, проанализировать выявленные проблемы и устранить их. CI-конвейер (workflow) — это набор команд, которые GitHub автоматически выполняет после изменений в репозитории.

В качестве инструментов рекомендуется использовать Pylint, Bandit и pip-audit. Допускается применение аналогов с сопоставимой функциональностью.

Этапы работы и критерии оценки подробно описаны в [tasks.md](tasks.md) и [assessment.md](assessment.md).

## Требования к окружению

- Установленный Python. Версию выбирает студент с учетом совместимости проекта и инструментов; для pip-audit нужен Python 3.10 или новее. Проверьте установку командой `py --version` в Windows или `python3 --version` в macOS/Linux. Если в Windows команда `py` не найдена, попробуйте `python --version` и замените `py` на `python` в команде создания окружения ниже.
- Аккаунт GitHub и доступ к вкладке **Actions** в своем репозитории.
- Редактор кода (например, VS Code) и терминал. В VS Code терминал открывается через **Терминал → Создать терминал**. Команды ниже выполняются из папки выбранного Python-проекта, а не из папки с этим заданием.

## Подготовка проекта

1. **Выберите проект.** Возьмите небольшой существующий Python-проект, который вам разрешено использовать, или создайте свой. Найдите его исходный код, инструкцию по запуску и файл зависимостей (`requirements.txt` или `pyproject.toml`), если он есть. Запишите, какой файл или модуль запускает приложение и где лежат тесты. Если проекта пока нет, сначала создайте рабочий Python-скрипт: следующие команды относятся к выбранному проекту.

2. **Разместите код на GitHub.** Войдите в GitHub, создайте личный репозиторий через **New repository**, откройте его и добавьте файлы проекта через **Add file → Upload files** либо отправьте их с помощью Git. Сохраните изменения коммитом и убедитесь, что файлы видны на странице репозитория. Создайте или откройте `.gitignore` и добавьте строку `.venv/`, чтобы локальное окружение из следующего пункта не попало в репозиторий. После дальнейших правок отправляйте обновленные файлы в тот же репозиторий.

3. **Создайте изолированное окружение.** Откройте папку проекта в редакторе и откройте терминал. Команда `pwd` в PowerShell/macOS/Linux покажет текущую папку; убедитесь, что это папка проекта. Выполните команды для своей системы:

   ```powershell
   # Windows, PowerShell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   ```bash
   # macOS/Linux, bash или zsh
   python3 -m venv .venv
   source .venv/bin/activate
   ```

   Первая команда создаст папку `.venv` с отдельным интерпретатором Python и местом для пакетов. Вторая подключит окружение к текущему терминалу; обычно в начале строки появится `(.venv)`. Проверьте путь командой `python -c "import sys; print(sys.executable)"`: он должен указывать на `.venv`. Если PowerShell запрещает запуск `Activate.ps1`, можно не менять настройки системы, а в следующих командах использовать `.\.venv\Scripts\python.exe` вместо `python`. В новом терминале окружение нужно подключить снова. Дополнительные требования приведены в [environment.md](environment.md).

4. **Установите зависимости.** Не закрывая терминал с активным окружением, проверьте, какой файл зависимостей есть в проекте. Если есть `requirements.txt`, выполните:

   ```bash
   python -m pip install -r requirements.txt
   ```

   Если проект устанавливается через `pyproject.toml`, следуйте его инструкции; для обычного устанавливаемого пакета часто подходит `python -m pip install -e .`. Установите выбранные инструменты проверок (пример для рекомендуемого набора):

   ```bash
   python -m pip install pytest pylint bandit pip-audit
   ```

   `pytest` запускает тесты, Pylint проверяет качество кода, Bandit ищет потенциально опасные конструкции, pip-audit проверяет зависимости на известные уязвимости. Если проекту нужны другие пакеты, установите их по инструкции проекта. Убедитесь, что установка завершилась без сообщения `ERROR`, а команда `python -m pip list` показывает установленные пакеты.

   Если у выбранного проекта нет файла зависимостей, создайте в его корне `requirements.txt`: в обычном текстовом файле запишите по одному **стороннему** пакету, который использует приложение, на строку. Например, строка `requests==2.32.3` означает пакет `requests` определенной версии; свою установленную версию посмотрите командой `python -m pip show requests`. Пакеты из стандартной библиотеки Python, например `json`, устанавливать и записывать не нужно. Если приложение не использует сторонних пакетов, создайте пустой `requirements.txt` для приведенного ниже примера CI или уберите из своего workflow команды с этим файлом.

   Инструменты проверок тоже должны устанавливаться в CI. Создайте рядом файл `requirements-dev.txt` и запишите в него `pytest`, `pylint`, `bandit`, `pip-audit` — по одному названию на строку. Рядом с каждым названием укажите установленную версию через `==`; ее можно найти командой `python -m pip freeze` (например, строка `pytest==8.3.5` показывает нужный формат). Загрузите оба файла в GitHub вместе с кодом и проверьте повторную установку командой `python -m pip install -r requirements.txt -r requirements-dev.txt`. Если в проекте уже есть `pyproject.toml` или другой способ управления зависимостями, используйте его и укажите соответствующую команду в своем README и workflow.

5. **Проверьте запуск на своем компьютере.** Оставаясь в папке проекта и в том же окружении, откройте README выбранного проекта и найдите раздел «Запуск» или «Usage». Скопируйте оттуда команду в терминал. Для собственного простого проекта с файлом `main.py` в корне выполните `python main.py`; если файл называется иначе, подставьте его имя. Ожидаемый результат зависит от проекта: программа должна выдать предусмотренный вами вывод или открыть страницу приложения без сообщения `Traceback`. Запущенный сервер может продолжать работать, пока вы не остановите его сочетанием `Ctrl+C`.

   Если в проекте есть тесты, выполните `python -m pytest`: убедитесь, что в итоговой строке есть `passed`, а `failed` нет. Сообщение `no tests ran` означает, что тесты не были найдены. Если видите `No such file`, проверьте текущую папку и имя файла; если `ModuleNotFoundError`, проверьте активацию `.venv` и установку зависимостей. После исправления повторите запуск. Запишите точные рабочие команды установки зависимостей и запуска в README своего проекта.

## Локальный запуск проверок

Запускайте проверки из корня выбранного проекта в терминале с активным окружением. Пример ниже подходит для проекта, в котором есть тесты, папка `src` с исходным кодом и файл `requirements.txt`:

```bash
python -m pytest
python -m pylint src
python -m bandit -r src
python -m pip_audit -r requirements.txt
```

Выполняйте команды по очереди и читайте сообщения каждой проверки. Если папки `src` нет, замените `src` на реальный путь к исходному коду. Если тестов нет, сначала добавьте их или уберите команду `pytest` из своего набора проверок. Для проекта без `requirements.txt` можно проверить пакеты активного окружения командой `python -m pip_audit`, но для повторяемой проверки в CI нужно зафиксировать зависимости проекта. При найденной проблеме сохраните исходный результат, исправьте код или версию зависимости и запустите ту же проверку повторно. Укажите в README своего проекта именно те команды, которые работают с его структурой. Допускается использование других инструментов с сопоставимой функциональностью.

## Настройка GitHub Actions

1. На странице своего репозитория в GitHub выберите **Add file → Create new file**. В поле имени введите `.github/workflows/ci.yml`: GitHub создаст нужные папки при сохранении файла. Если работаете в локальном редакторе, создайте те же папки и файл в корне проекта, а затем отправьте файл в репозиторий.
2. В файле задайте запуск по событиям `push` (отправка изменений) и `pull_request` (запрос на слияние). Добавьте шаги получения кода, установки нужной версии Python и зависимостей, затем запускайте те же проверки, которые отработали локально.
3. Скопируйте пример ниже в `ci.yml`. Он рассчитан на проект с Python 3.13, файлами `requirements.txt` и `requirements-dev.txt`, папкой `src` и тестами. Замените версию Python, пути и команды согласно своему проекту. Если тестов нет, удалите шаг `Run tests`; если файлы зависимостей называются иначе, измените команды их установки и проверки.

   ```yaml
   name: CI

   on: [push, pull_request]

   jobs:
     checks:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v7
         - uses: actions/setup-python@v7
           with:
             python-version: '3.13'
         - name: Install dependencies and tools
           run: |
             python -m pip install -r requirements.txt -r requirements-dev.txt
         - name: Run tests
           run: python -m pytest
         - name: Check code quality
           run: python -m pylint src
         - name: Check code security
           run: python -m bandit -r src
         - name: Audit dependencies
           run: python -m pip_audit -r requirements.txt
   ```

4. Нажмите **Commit changes**, чтобы сохранить `ci.yml` в репозитории. Откройте вкладку **Actions**, выберите запуск **CI**, затем задачу `checks` и нужный шаг. Успешный статус означает, что все шаги прошли; при ошибке откройте журнал неуспешного шага и прочитайте причину. Исправьте ее, сохраните новый коммит и проверьте следующий запуск. Для проверки `pull_request` создайте в репозитории отдельную ветку, внесите в нее изменение и нажмите **Compare & pull request**; убедитесь, что проверка запустилась и для этого запроса. Дополнительные примеры есть в [документации GitHub](https://docs.github.com/en/actions/tutorials/build-and-test-code/python).

## Ожидаемый результат

После выполнения задания должны быть получены:

- GitHub-репозиторий с исходным кодом и workflow-файлом в папке `.github/workflows`.
- История запусков во вкладке **Actions**, показывающая автоматическую проверку после `push` и `pull_request`.
- Результаты тестов и проверок безопасности до и после исправлений в журналах соответствующих запусков.
- Исправленный код или обновленные зависимости, для которых повторные проверки проходят успешно.
- Краткий отчет `REPORT.md` с описанием найденных проблем, действий по исправлению и результатов повторных проверок.

## Формат сдачи

Создайте `REPORT.md` в корне своего GitHub-репозитория. Укажите в нем выбранный проект и инструменты, найденные проблемы, способы их исправления, результаты проверок до и после изменений и ссылку на видеоролик. Убедитесь, что преподавателю доступны исходный код, workflow-файл, отчет и история запусков во вкладке **Actions**. Затем предоставьте ссылку на репозиторий.

Запишите видеоролик с демонстрацией работы продолжительностью до 4 минут: покажите запуск проверок и их результаты в GitHub Actions. Загрузите ролик на Яндекс Диск или Google Диск, включите доступ по ссылке и добавьте эту ссылку в `REPORT.md`. Проверьте, что ссылка открывается без входа в ваш аккаунт.
