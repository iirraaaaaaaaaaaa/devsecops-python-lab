## Критерии проверки

Для оценки задания используются автоматизированные проверки и результаты выполнения GitHub Actions.

### Проверяемые сценарии

**1. Проверка исходного состояния**

В учебном проекте предусмотрены намеренно внесённые проблемы. При первоначальном запуске часть проверок должна завершаться с ошибкой.

**2. Проверка автоматизации**

При внесении изменений в репозиторий GitHub Actions должен автоматически запускать тесты, статический анализ кода и аудит зависимостей.

**3. Проверка обнаружения уязвимостей**

Конвейер должен фиксировать заранее подготовленные проблемы безопасности. Например, использование потенциально небезопасного вызова `subprocess` с `shell=True`.

**4. Проверка исправлений**

После устранения подготовленной уязвимости соответствующий тест должен успешно проходить, а предупреждение анализатора — исчезнуть.

**5. Проверка итогового состояния**

После выполнения обязательных исправлений все проверки, настроенные как обязательные, должны завершаться успешно.

### Критерии успешного выполнения

- Workflow автоматически запускается при push и pull request.
- Инструменты анализа корректно подключены и выполняются.
- Подготовленные ошибки обнаруживаются.
- Исправления приводят к ожидаемому изменению статуса проверок.
- Результаты документируются в отчёте.
- Дополнительные задания реализованы в соответствии с выбранным уровнем сложности.
