## Критерии проверки

Для оценки задания используются автоматизированные проверки и результаты выполнения GitHub Actions.

### Проверяемые сценарии

**1. Проверка исходного состояния**

Студент выполняет первоначальный запуск выбранных инструментов анализа и фиксирует полученные результаты.

**2. Проверка автоматизации**

При выполнении push и создании pull request GitHub Actions автоматически запускает настроенные проверки.

**3. Проверка обнаружения уязвимостей**

Студент демонстрирует воспроизводимый пример проблемы безопасности, обнаруживаемой выбранным анализатором. Допускается использование специально подготовленного учебного примера.

**4. Проверка исправлений**

После устранения продемонстрированной проблемы соответствующая проверка должна завершаться успешно. В отчете фиксируются результаты до и после исправления.

**5. Проверка итогового состояния**

Все проверки, определенные как обязательные, должны завершаться успешно. Результаты запусков доступны в GitHub Actions.

### Критерии успешного выполнения

- Workflow автоматически запускается при push и pull request.
- Инструменты анализа корректно подключены и выполняются.
- Подготовленные ошибки обнаруживаются.
- Исправления приводят к ожидаемому изменению статуса проверок.
- Результаты документируются в отчете.
- Дополнительные задания реализованы в соответствии с выбранным уровнем сложности.
